# C08 · Rehearsal & Documentation

**Meetings:** D104–D105 · **Points:** 15 pts

**Video/Source Link(s):** None.

**Notes**  
Record a demo video this week as a backup. Live demos fail at symposiums: network, API rate limits, a laptop that decides to update. A recorded fallback is not defeatism, it is what professionals do.

Dry run in front of your assigned peer project. They will tell you what didn't land. Listen to them; they are a better proxy for the audience than you are.

Eight minutes is shorter than you think. Time it. Most first attempts run twelve.

Your README should let a stranger run this thing. Test that claim on a classmate who has never seen your project.

**Deliverable**  
README that a stranger can follow + recorded demo video + completed dry run with written peer feedback + timed 8-minute script.

**Reflection Questions**

1. How long did your first untimed run-through take? What did you cut to get to eight minutes?
2. What did your peer reviewer not understand on the first pass?
3. Did your classmate get your project running from the README alone? What was missing?
4. What are you going to say in the first thirty seconds? Write it out.
5. What is the one question from the audience you are least prepared for?
