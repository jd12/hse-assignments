# C04 · Sprint 2 + Peer Code Review

**Meetings:** D92–D94 · **Points:** 15 pts

**Video/Source Link(s):** None.

**Notes**  
Cross-project code review this week. You will be assigned another project (solos review solos, pairs review pairs) and you will deliver written feedback.

**You are graded on the review you give, not the one you receive.** A review that says "looks good" scores zero. A review that finds one real problem, with a file:line citation and a description of how it fails, scores full marks even if the rest of the codebase is fine.

Read their eval plan first, then their code. Ask whether the code actually measures what the plan says it measures. That gap is where most of the findings will be.

**Deliverable**  
Sprint 2 commits + written review of your assigned project (minimum 3 findings with file:line) + a one-paragraph response to the review you received saying what you'll act on and what you won't.

**Reflection Questions**

1. What was the strongest finding in the review you gave? Cite the file:line.
2. What did reviewing someone else's project make you notice about your own?
3. What in the review you received are you not going to act on, and why?
4. Does their code measure what their eval plan claims it measures? Where does it diverge?
5. What is your project's current number on your success metric? How far from your target?
